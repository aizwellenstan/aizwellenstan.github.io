CH06｜Synchronization Tools
先問：
誰在改
共享資料？

多行程/多執行緒同時存取共享狀態，若交錯執行就會產生 race condition。核心概念是 critical section：同一時間只允許一條執行路徑進入修改共享資料。

Mutex
最直覺：互斥進出臨界區。
Semaphore
可做二元/計數，控制「資源數」。
Monitor
把互斥 + 條件等待封裝成高階抽象。
一句話記憶
同步不是背 API，是確保「臨界區一次只給一個人」；工具只是實作手段。

CH06｜Liveness & 評估
互斥夠了？
還要
公平與活性

除了互斥，還要看 liveness： deadlock（互卡）、starvation（永遠輪不到）是不同問題。

Priority inversion（常考概念）

低優先序拿著鎖 → 高優先序等鎖 → 中優先序一直插隊，讓高優先序等更久。常見解： priority inheritance（持鎖者暫時繼承高優先序）。

CAS vs Mutex（效能直覺）
CAS 常在低到中等競爭更快；但在極高競爭下，傳統鎖機制可能反而更穩。

CH08｜Deadlocks
四條件
同時成立
才會死結

死結的判斷：四個必要條件同時成立才會卡死。

Mutual exclusion
資源不可共享。
Hold and wait
拿著一個，還想再等。
No preemption
不能硬搶資源。
Circular wait
等待形成環。
處理策略（四選一）
ignore（鴕鳥）／prevention（拆條件）／avoidance（Banker，safe state）／detection + recovery（偵測後終止或搶占資源）。

CH09｜Main Memory

位址翻譯核心：logical 是程式看到的， physical 是實體位置；MMU 負責轉換。

配置方式對比
方式 優點 常見痛點
Contiguous allocation 概念簡單，直接切一塊連續記憶體 external fragmentation（空洞不連續）
Paging 避免外部碎裂，配合 TLB 加速 page table 成本 + TLB miss 代價
Swapping（現代常見變形）
傳統「整個行程換出/換入」太慢；多改成 page-out / page-in（配合 paging）。行動裝置通常不做傳統 swapping，改以回收/終止策略釋放記憶體。

CH10｜Virtual Memory

virtual memory 讓程式「看起來」有更大的記憶體；典型做法是 demand paging：用到才載入。

Page replacement（最常考）
FIFO（可能有 Belady anomaly）／OPT（理論最優）／LRU（符合 locality，常用近似法）。
Thrashing 與 TLB Reach
working set 放不進 frames → fault 爆炸就是 thrashing。
TLB Reach = (TLB size) × (page size)：想覆蓋 working set，得靠更大頁或多種頁大小。
